4.1 Tech Stack
- React 18.3.1

- Vite 5.x
- Tailwind CSS 3.4.x
- Framer Motion 12.x

- react-hot-toast

4.2 Frontend entrypoint and composition
- main.jsx mounts App in React.StrictMode.
- App.jsx wraps app with:
  - AuthProvider
  - BrowserRouter
  - ToastProvider
  - AnimatedRoutes with AnimatePresence route transitions

4.3 Client route map
Defined in client/src/App.jsx:
- /login -> Login page
- /register -> Register page
- /forgot-password -> ForgotPassword page
- /reset-password -> ResetPassword page
- /auth/callback -> OAuth callback page
- / -> ProtectedRoute -> Dashboard page
- /verify-email -> ProtectedRoute -> VerifyEmail page
- /workspaces -> ProtectedRoute -> WorkspaceSelector page
- * -> redirect to /

4.4 Access control model (frontend)
- ProtectedRoute checks AuthContext
  - if loading: shows loading UI
  - if not authenticated: redirects to /login
  - if authenticated: renders children

4.5 Context layer
- AuthContext
  - owns user session state
  - exposes login/register/logout/guest/google login/refreshUser
  - calls /api/auth/me on startup
  - applies user appearance settings to document root (theme + font scale)
- SocketContext
  - wraps useSocket hook and provides socket API across app
- OnlineStatusContext
  - tracks and surfaces online/presence status (used in dashboard ecosystem)

4.6 Primary page architecture

Dashboard page (client/src/pages/Dashboard.jsx):
- Main orchestration page for collaboration UX
- Provides:
  - workspace/team/channel selection
  - DM selection
  - channel chat rendering
  - dashboard home widgets when no chat selected
  - smart search modal and filters
  - notifications, profile dropdown, settings modal
  - invitation modal and pending invitations panel
  - role-based management context menu actions
  - snooze + follow-up reminder controls
- Layout:
  - AppShell
  - Sidebar
  - TopBar
  - content body with DashboardHome or ChatWindow

WorkspaceSelector page:
- reads user workspaces
- allows new workspace creation
- displays workspace cards

Auth pages:
- Login: email/password, Google login, guest login
- Register: name/email/password/username with debounced username availability check
- VerifyEmail: OTP verify + resend
- ForgotPassword: request reset code
- ResetPassword: submit email+otp+new password
- Callback: refresh user after OAuth redirect

UsernameSetup page:
- forced modal-like flow for users without username
- validates username format and availability
- calls /api/username/set

1. load dotenv via import 'dotenv/config'
2. connectDB()
3. create HTTP server from Express app
4. init Socket.IO server on same HTTP server

6. passport.initialize()

9) SOCKET.IO ARCHITECTURE
================================================================================

Server file:
- server/src/sockets/index.js

Socket auth:
- handshake expects token in auth.token or query.token
- token verified with JWT secret
- socket.data.user and socket.data.userId set

Online presence:
- onlineUsers map (userId -> socket ids)
- emits user:online and user:offline
- emits users:online snapshot on connect

Rooms:
- user:{userId} for personal notifications
- channel:{channelId} for channel messages

Inbound events:
- join-channel(channelId, callback)
- leave-channel(channelId)
- send-message({channelId, content}, callback)
- user:typing(channelId)
- user:stopTyping(channelId)

Outbound events:
- users:online
- user:online
- user:offline
- message:history
- message:new
- user:typing
- user:stopTyping
- new_notification

Important behaviors:
- canAccessChannel guard on join/send
- message send requires email verified
- mention detection using @username pattern
- mention notifications emitted to user rooms
- DM channels also emit message:new to user:{participantId}

Companion helper:
- server/src/socket/notificationHandlers.js provides sendNotification(io, data)

================================================================================
10) SCHEDULERS, BACKGROUND PROCESSING, AND EMAIL
================================================================================

scheduler.service.js
- startSchedulers
  - reminder processor interval: 15s
  - scheduled message processor interval: 10s
- stopSchedulers

Due reminder processing:
- queries Reminder pending items with remindAt <= now
- creates Notification(type=reminder)
- emits new_notification to user room
- marks reminders sent

Scheduled message processing:
- queries ScheduledMessage pending items with sendAt <= now
- creates Message
- emits message:new to channel room
- if DM channel, emits message:new to each participant room
- marks scheduled messages sent

emailService.js
- SMTP transport if SMTP_HOST + SMTP_USER present
- fallback Ethereal transport for dev/test
- queue model:
  - if REDIS_URL: Bull queue
  - else in-memory immediate queue with retry backoff
- exposes:
  - enqueueMail
  - sendOtpEmail
  - sendPasswordResetEmail
  - onMailSent(test hook)

rateLimiter.js
- OTP and reset mail rate limiting
- Redis-backed if REDIS_URL, otherwise in-memory map
- exports:
  - canSendOtp
  - canSendPasswordReset
  - resetForTests

12) CORE APPLICATION FLOWS
================================================================================

12.1 Authentication flow
- Register/login/guest through /api/auth
- httpOnly token cookie used for session
- /api/auth/me used by frontend bootstrapping in AuthContext
- optional Google OAuth via /api/auth/google + callback

12.2 Email verification flow
- user requests OTP via /api/auth/send-otp
- verifies via /api/auth/verify-email
- some write actions require verified email (middleware enforced)

12.3 Password reset flow
- request OTP via /api/auth/request-password-reset
- submit reset via /api/auth/reset-password

12.4 Workspace-team-channel hierarchy flow
- workspace created first
- team belongs to workspace
- channel belongs to team (except DM)
- access checks done by workspace/rbac/channelAccess rules

12.5 Invitations flow
- invitation scope controls downstream access model:
  - workspace scope
  - team scope
  - channel scope
- acceptance endpoint updates membership visibility domain
- invitation TTL auto-expiry after 7 days

12.6 Messaging and threads flow
- initial history via REST + socket join callbacks
- real-time send via socket send-message
- replies represented by parentMessageId/threadId
- reactions, updates, deletes via REST + socket propagation

12.7 DM flow
- /api/dm/start checks accepted connection requirement
- reuses existing DM channel or creates one
- DM channels marked isDM=true and use dmParticipants

12.8 Search flow
- /api/search performs scoped message/user/channel/file lookup
- scope constrained by workspace access and canAccessChannel

12.9 Notification flow
- notifications persisted in Notification model
- read APIs for single/all
- socket new_notification event for real-time UX

12.10 Reminder + scheduled messaging flow
- reminders and scheduled messages created through /api/reminders
- scheduler interval jobs emit notifications and messages when due
